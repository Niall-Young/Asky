# 历史拒绝说法覆盖图片能力的回归修复

日期：2026-11-17。

## 复现与改动

用户在上一轮 Debug 中提问“钟丽缇是什么明星啊”，回复没有图片，仍说无法直接贴图。确认运行的是 Debug 路径，二进制中包含上一轮新增图片提示词；该轮会话记录没有工具调用，用户输入上下文携带约 16,799 字符的记忆与历史，末尾包含多次“不能贴图”的旧回复。图片尚未生成，因而不是渲染器漏图。

新增按当前工具目录启用的每轮 system 能力提示，放在历史与工具结果之后，要求合适的介绍/视觉问题先读取真实图片候选再作答，同时遵守纯文字、不联网和无可用图片时的退路。提示仅在当前目录有 web_read_page 时启用，不保存到会话、不用于压缩请求，不修改或删除用户历史。

随后在用户完整历史的实际聊天窗口中复测，中间版本虽然调用了读取工具，但只重读百度百科和豆瓣，没有搜索新来源，最终仍无图片。因此补充“旧页面无图时搜索对象名加照片，并读取 1–2 个新来源”的有界回退，同时要求继续回答原问题，不能只汇报找图失败。

## 实际验证

- 加修复前，以当前配置的真实模型、简短的旧拒绝历史及相同问题进行 opt-in 回归：0 次工具调用、0 张图片；测试按预期失败。回答变成“要不要我找几张照片”，仍未主动完成。
- 加修复后，同一模型与输入：调用 web_read_page、web_search、web_read_page、web_read_page，最终 1 张 Markdown 图片；通过 ChatImageService 下载解码，照片来自 https://www.tvmao.com/star/UiA4，直链为 https://pix2.tvzhe.com/thumb/star/0/419/260x346.jpg。真实回归约 65.5 秒，正文与图片需经历来源回退；不是速度基准或所有网站可用性的保证。
- 纯文字负例“用纯文字简单介绍钟丽缇，不要配图”：0 工具调用、0 图片、无错误，通过，约 2.4 秒。
- 全量 KulaCore swift test：388 个测试、13 个测试目标通过（含默认提前返回的 opt-in 测试）。新增运行时回归覆盖有/无图片工具、工具前后都携带能力提示、提示不落入快照。
- xcodegen generate 与 README 的 Debug xcodebuild：通过。git diff --check：通过。
- 中英文 README 同步每轮能力提示行为，运行时文档补充 opt-in 检查方法。

真实模型使用隔离内存数据库与临时会话；配置导出文件仅包含模型地址、名称和 Keychain 引用，密钥不写入文件与日志。回归报告放在 /tmp。构建产物沿用现有 build/、Packages/KulaCore/.build/ 与 Asky.xcodeproj/ 忽略规则，无新增忽略规则。

## 最终真实界面验收

- 重启最后构建的 Debug 包，通过进程路径确认 PID 46549 运行 `build/DerivedData/Build/Products/Debug/Asky.app/Contents/MacOS/Asky --show-agent`；未替换 /Applications 的正式安装版。
- 在保留用户完整历史的 AI 窗口输入并发送同一句“钟丽缇是什么明星啊”，没有追加“给图片”或指定图片来源。
- 实际调用先读取百度百科、豆瓣（均返回 0 个候选），随后搜索“钟丽缇 Christy Chung 照片 人像”，从结果读取 Far East Films 与 8world 页面，分别得到 8、5 个候选。
- 最终回答自动包含 2 张 Markdown 图片；CUA AX 树显示两处图像、下载按钮及对应来源链接，截图可见照片实际加载，最终停在 8world 照片处。未改写已有回答或手工向历史插图。
- 最终提示词的另一项真实模型检查：“水豚长什么样，简单介绍一下”返回 2 张图，首图经 ChatImageService 下载解码成功，约 18.2 秒。
- 上述检查证明本次模型/来源/问题上的实际效果；没有声称所有模型、任意网页都能稳定返回照片，图片来源失败仍允许有界退回文字。
