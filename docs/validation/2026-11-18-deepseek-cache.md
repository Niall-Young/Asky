# DeepSeek 输入缓存对照测试

2026 年 11 月 18 日，在同一台 Mac、同一账户和官方端点的 `deepseek-flash` 上，以原生 AgentHost 比较修复前后。旧版取自提交 `70e2371`，只在临时副本的流解码器中输出服务端用量。新版使用相同的问题、工具定义和合成历史。四个用户回合各建新快照，间隔约 3 秒。每次将上一个问题和实际回答追加到测试历史，第四回合调用一次样品编号工具。会话写入独立临时目录。

| 请求 | 修复前命中 | 修复前未命中 | 修复后命中 | 修复后未命中 |
| --- | ---: | ---: | ---: | ---: |
| 首次提问 | 512 | 5,966 | 512 | 5,986 |
| 第二次提问 | 512 | 5,985 | 6,272 | 246 |
| 第三次提问 | 512 | 6,005 | 6,400 | 138 |
| 第四次提问，准备调用工具 | 512 | 6,028 | 6,400 | 161 |
| 工具结果返回后生成答案 | 5,248 | 1,372 | 6,400 | 241 |

第二至第四次提问合计，输入 token 命中率由 7.9% 升至 97.2%。包含首次请求及工具续轮，五次加权命中率由 22.3% 升至 79.3%。两版都取得了工具实际返回的编号。新版 macOS 统一日志记录四条 initial 和一条 continuation，数值与 DeepSeek 响应逐项相符。

此次对照覆盖可复用的长历史和一项只读工具。真实时间线的历史选择、工具与插件配置、提问间隔以及服务端缓存状态均会影响日常命中率。

## 本地验证

- 使用 Xcode 工具链运行 KulaCore 的完整 `swift test`，命令通过。新增回归检查跨提交的固定提示、随轮更新时间、工具续轮的已有消息、其他兼容端点的请求选项，以及两种流式用量返回位置。
- 显式启用 `CacheLiveTests`，旧版和新版各完成五个真实模型请求。新版默认测试采取显式启用开关。复现命令见 [DeepSeek 输入缓存](../agent-runtime.md#deepseek-输入缓存)。
- 运行 `xcodegen generate` 和 README 的 Debug 构建命令，均成功。在线测试经原生 AgentHost 和 HTTP 客户端运行，未通过聊天窗口发送测试消息。
