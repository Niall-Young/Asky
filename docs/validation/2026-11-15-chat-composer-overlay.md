# 连续聊天容器与底部渐进模糊

## 改动

- 聊天滚动区延伸到整个窗口底部，输入框叠放其上，正文不再在输入框顶边截断。
- 底部复用顶部渐进模糊组件，反转蒙版，使模糊半径从上方 0 pt 向底边增加至 6 pt。范围随输入框实测高度加 24 pt 调整，不叠加颜色，不模糊输入控件，也不接收交互；降低透明度时隐藏装饰。
- 用 `onGeometryChange` 测量包含底部间距的输入框高度，消息尾部留白和回到底部按钮位置同步调整。最后一条消息可完整滚到输入框上方，多行输入同样适用。
- 同步中英文 README 和设计系统。

## 实际验证

- `xcodegen generate` 与 README 中的 Debug `xcodebuild` 命令通过。
- `cd Packages/KulaCore && DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test` 通过，Swift Testing 为 53 项。首次未指定 Xcode 时因 XCTest 不可用失败，改用完整 Xcode 后成功；一次误在根目录调用 swift test 无 Package.swift，已在正确目录重跑。
- `--bottom-push` 通过：固定窗口、短消息自然排列、长回复从开头阅读、溢出聊天、新问题与等待状态；新增断言检查滚动区覆盖整窗、最后回复位于输入框上方，以及六行输入增高后滚动留白同步增加。
- `--reading-scroll` 通过：手动阅读位置保留，回到底部三次点击均得到 0 pt 底部差距。测试点击坐标改为从输入框实际位置计算，以适配悬浮布局。
- 上述两项均通过 `--preview-macos14` 兼容分支；这只是当前系统上的兼容路径测试，并非 macOS 14 实机验证。
- 查看新回归窗口浅色/深色屏幕截图，确认文字经过输入框后方并在底部渐进模糊。窗口捕获带透明度，不以其颜色作为固定色值依据。
- 重启最新 Debug Asky，通过电脑工具打开实际聊天窗口并查看截图：同一历史长回复连续延伸到输入框后方，底部模糊由清晰向下增加，控件保持清晰。进程路径为本项目 `build/DerivedData/Build/Products/Debug/Asky.app/Contents/MacOS/Asky`，启动时间晚于最后构建。没有发送真实 AI 请求。

## 过程中发现并修复

- 初版用 PreferenceKey 测高，多行输入回归发现文档高度未同步变化；改为 `onGeometryChange` 后通过。
- 回到底部测试初次仍按原滚动区底边点击，点到了输入区；更新为当前按钮位置后，现代及兼容分支均通过。
- 并行任务正在修改同一源文件与构建对象，多次直接编译被 Swift 的输入文件变更检查中断。将源文件和链接对象复制到既有忽略目录 `build/composer-verification/` 后，使用原回归 runner 的本地副本编译稳定快照，仍运行实际 App 源码与回归程序；随后完成最终 App 构建。其他任务的头像和表情修改未纳入本次提交。

截图、回归程序、构建产物和快照均复用既有 `build/` 忽略规则；核心测试产物复用 `Packages/KulaCore/.build/`。未打包或发布正式安装包。
