# Asky Swift Agent Runtime

更新日期：2026 年 11 月 14 日。当前实现已替换 Pi / TypeScript Agent 宿主，模型与工具编排在 Swift 中运行。验证范围见 [迁移记录](validation/2026-11-14-native-agent.md)。

## 架构与参考

Asky 保留 AgentHost 的任务事件和 ToolService 的原生权限边界。NativeRuntime 是进程内 Swift actor，不启动 Node、Pi 或其他模型辅助进程。既有 JSONL v2 事件在内存通道传递，用于沿用宿主生命周期和 UI；负数 runtime identity 只作实例标识，不是 OS PID，runningPID 为 nil。

参考 [Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/)、[Codex 上下文管理](https://github.com/openai/codex/blob/main/codex-rs/core/src/compact.rs) 和 [oh-my-pi agent loop](https://github.com/can1357/oh-my-pi/blob/main/packages/agent/src/agent-loop.ts) 的循环、事件、流式工具参数和恢复边界，自行实现 Asky 所需能力。没有引入这些项目的运行依赖，也不复制完整终端、IDE、LSP、自由 Shell 或多 Agent 系统。

| 能力 | 当前实现 |
| --- | --- |
| 模型 | Foundation URLSession，OpenAI-compatible Chat Completions，BYOK；文字、图像、流式工具参数；JSON 响应兼容 |
| 事件 | 工具事件与 textDelta 保留在运行时和记录层；界面等待时只显示三点气泡，本轮结束后展示权威完整回复 |
| 工具 | 当前允许目录的原生工具和已启用插件；调用全部交给 ToolService，未知工具不执行 |
| 原生交互 | ask_user 结束当前轮等待补充；asky-form 保持现有 SwiftUI 控件与逐行解析 |
| 上下文 | 动态时间、来源片段、Markdown 记忆、附件引用与插件指导；不发现全局 .pi、AGENTS、skills 或 shell 配置 |
| 会话 | ToolService 管理原生 JSON 快照，Pi 活动分支按需迁移，保留未完成工具的待核实结果 |
| 压缩 | 上下文序列化大小超过 180,000 字节后在用户轮边界总结旧轮，保留完整工具往返；字节预算不等于精确 token 计数 |
| 资源 | 只在提交 AI 请求时创建运行时；任务完成释放消息，默认空闲 60 秒销毁运行时；不做模型预热 |
| 插件 | API v2 本机可执行文件，无 Node；API v1 通过独立兼容脚本使用本机 Node，见[插件文档](plugins.md) |

## 模型与凭据

模型 Key 由主应用从 Keychain 取出，只保存在内存请求中，不写会话、配置、命令行或插件环境。使用 ephemeral URLSession，关闭缓存、Cookie 与凭据存储；拒绝 HTTP 重定向以免转发 Key。API 使用 HTTPS，回环本机调试端点可用 HTTP。

流式 SSE 按字节组帧，聚合碎片工具名、ID 和 JSON 参数；完整输出确认后才允许调用工具。模型输出与工具参数总量上限 1 MiB，单次最多 128 个调用；格式无效、输出中断、达到生成长度上限不报告成功。保留提供方返回的 reasoning_content 供工具续轮使用，不作为正文展示；DeepSeek 官方端点默认关闭 thinking，与旧运行时保持一致（[提供方协议](https://api-docs.deepseek.com/guides/thinking_mode/)）。单请求超时 120 秒；429、5xx 及未输出正文前的瞬时网络故障最多重试一次。工具不因模型网络重试而重新执行。

本轮工具调用最多 50 次。相邻的公开网页搜索与读页（只读、无需确认）最多三个并发，任一完成即补入下一项独立网页请求，不等待最慢请求完成整批；结果按原调用顺序归档；写操作、插件、其他工具及补充提问仍是串行边界。ToolService 继续负责参数、权限、确认、去重、执行与回读。全部网页来源均处于冷却且本次请求未实际访问任何来源时，本轮保持工具目录不变以复用输入缓存，同时在运行时拦截后续搜索/读页调用并提示模型使用已取得资料收尾，避免换词空转；后续用户提交可重新尝试。写工具的 userRequested 仅表示本轮明确意图，转发前剥离，不是用户批准。awaitingConfirmation、rejected、suggestion 和 pendingVerification 都不得当作成功。

## 公开信息与联网核实

`NativeAgentPrompt` 在系统提示词前部要求先核实可能变化的公开信息，不依赖用户是否说“最新”或“联网”。范围包括推荐与比较、软件/API 用法和不确定事实；稳定基础概念、翻译、润色和纯计算可直接回答，用户明确不联网时遵从。`web_search` 的中英文工具描述同步声明触发条件。结果必须匹配对象、版本与时间，并在相关陈述旁链接来源；搜索失败或摘要不足不能用训练知识冒充当前事实，也不能声称已读取网页全文。

摘要足以支持具体答案时直接回答并附来源，不例行声明阅读范围。摘要不足时继续核实；仍缺关键信息才说明具体缺口与下一步，不能用摘要冒充全文分析。工具返回的 notice、quality 等用于内部判断，不逐字转述为免责声明；用户直接询问核实过程时如实回答。

`NativeAgentPrompt` 也定义主动配图判断：视觉识别、景点/人物/生物介绍及外观比较通常配图，日期、参数、代码、翻译与纯文字任务无需装饰性图片。模型先找准确页面；搜索摘录足够回答、只缺图片时，调用 `web_read_page` 并设置 `imagesOnly:true`，直接提取图片元数据而不再请求正文服务；确实缺少正文才设置 `includeImages:true`；核对候选的对象、型号和图注，使用独立 Markdown 图片段落与来源链接，通常 1–3 张。候选元数据不等于视觉验证；不得猜图链、把网页当图片或用生成图冒充真实照片。缺图时保留文字回答，遵循用户不联网或不配图的要求。

最终回复由运行时执行配图校验：Markdown 图片地址必须来自成功工具结果的 images / 正文图片，或当前用户原文中的链接。历史 assistant 的图片不构成来源证据，模型也不能改写候选域名、文件名或尺寸。没有来源的草稿不落盘、不进入回复或工具叙述；最多提示模型纠正一次，imagesOnly 收尾后仍不重开网页工具。随后通过 ToolService 的 ChatImageService 并发下载并解码所有选中图片，最多三个并发、整批 5 秒预算，成功缩略图供 UI 缓存复用；失败的图片与紧邻的独立图片来源标注移除，保留其余正文。取消会中断校验且不发布草稿。

模型连接仍接收 SSE，但运行时在完整消息到达且图片校验完成后才发出正文 textDelta / message，工具前叙述只保留文字，避免被拦截的草稿通过叙述事件进入历史。

每次实际对话请求在顶部固定 system 提示词中并入配图能力说明，仅在本轮工具目录包含 `web_read_page` 时启用；明确可显示 Markdown 图片、适合配图时先取候选、尊重纯文字/不联网要求，且找图失败不等于客户端不能显示图片。已有页面无图时要求按对象名加“照片”或 portrait/photo 搜索替代来源，再检查 1 个新页面，每个对象最多检查两个不同页面，独立查询尽量同批提交，已有相关图片不再补搜；不只重读旧链接后过早放弃。该提示不写入会话快照，也不用于无工具的上下文压缩请求，并随顶部 system 提示词复用输入缓存。

普通多对象介绍或比较先尝试一次覆盖全部对象的查询，缺资料才补查。默认用一句结论、紧凑对比表和必要配图解释核心区别，正文约 300–600 字，不自行扩展票价、营业时间或详细历史；用户明确要求长文、攻略或深入研究时遵从。仅图片元数据不能支持新的正文事实。完全由 imagesOnly 读页构成的一批调用完成后，运行时保持工具目录不变以复用输入缓存，同时拦截后续网页搜索/读页调用并要求使用已有证据和可用图片直接作答，保留正文事实段落的 Markdown 来源链接（避免只给配图附来源）；实际结果缺图也不再次补搜。混合其他操作的批次不会提前结束研究，写入及其他工具不受影响。

这些是模型指令，运行时仍使用 `tool_choice: auto`，没有基于关键词强制搜索；不保证所有模型都遵循。联网开关与 ToolService 权限保持不变。

## 网页上下文预算

模型请求中的网页正文与搜索摘录采用 UTF-8 字节预算：每个工具结果最多 12,000 字节，本轮所有网页结果的正文摘录最多 48,000 字节，按调用顺序从剩余预算中逐条分配，不回改此前已发送的网页结果，从而保留同轮续轮的前缀缓存。仅截取 text/snippet，保留来源 URL、图片候选、错误状态和完整工具调用配对；截取处标记 truncated/contextTruncated，不能把省略部分当作已读证据。原始完整结果仍保存在本地快照，写操作结果不压缩。此请求投影不需要额外摘要模型调用，也适用于只有一个 user 消息的工具循环；旧轮的 180,000 字节摘要规则继续保留。

## 会话、取消与恢复

运行时快照为 runtime/native-sessions/<sessionID>.json；SQLite 保存分页 UI 与检索投影及工具执行记录。每次模型完整消息和工具结果（并发网页读取在该批返回后）原子保存快照。图片以引用落盘，仅在网络边界展开为 Base64；单张读取上限 20 MiB，文本附件最多读取 64 KiB，每轮最多 16 个附件。附件缺失会提供不可读取信息，不伪造图片内容。

旧 runtime/pi/sessions/ 日志只允许从应用自有目录读取，按最后活动叶节点的 parentId 链迁移，应用压缩摘要和保留边界，不合并废弃分支。原文件保留；同一会话后续优先读取原生快照。未知格式和越界路径显式失败。原生快照总量上限 32 MiB，文件权限 0600、目录 0700。

取消会停止网络请求和宿主管理的工具任务；已有写入或在途调用显示待核实，不承诺回滚。已记录调用缺少结果时，恢复只补入未知结果，绝不重放工具。隐藏窗口不取消任务。退出会等待取消任务完成后关闭通道，不保留模型子进程。

进入历史或设置、普通搜索、确定性提醒与外部 MCP 不启动模型。后台 AI 仍遵循现有显式授权，来源管理仍归原生系统。

## 完整回复中的原生表单（试用）

`textDelta` 仅缓存在模型层，最终 `message` 确认完整内容，本轮结束后展示回复气泡，协议 v2 无新增事件。工具前的文字在 toolCall 边界转存为 tool_narration 过程记录，仅保存、不展示；它不作为 assistant 最终答复，也不参与普通用户/助手消息的记忆提炼。工具调用、压缩状态与过程耗时均不进入对话界面，等待期间统一显示三点气泡。`ChatFormParser` 按 JSON 行解析字段，原生表单仍在完整回复结束后一次显示，`ChatReplyView` 将它们映射为固定的 SwiftUI 控件。模型不输出可执行 Swift 或 HTML；没有 WebView、脚本与任意系统动作入口。

回复中最多包含一个独立的 `asky-form` 围栏，第一行标题，此后每行一个字段：

````text
请补充会议信息：
```asky-form
{"title":"会议安排"}
{"id":"title","type":"text","label":"会议名称","required":true}
{"id":"duration","type":"radio","label":"时长","options":["30 分钟","60 分钟"],"required":true}
{"id":"topics","type":"multi","label":"议题","options":["设计","开发"]}
{"id":"day","type":"date","label":"日期","required":true}
{"id":"start","type":"time","label":"开始时间","components":["hour","minute","second"],"required":true}
{"id":"countdown","type":"duration","label":"倒计时","components":["minute","second"]}
```
````

`radio` 使用原生圆形单选按钮组，`select` 保留下拉单选，`multi` 为复选框多选。radio 未提供有效 `defaultValue` 时初始不选中，不同字段的单选组互相隔离；与 select 共用选项和提交校验，默认只接受一个合法选项；radio/select 可带 `allowCustom:true`，增加「自己填写」入口，选中后显示文本输入。选项与自填互斥，切换选项保留自填草稿；提交当前答案，不发送内部选项标记。自填不得为空白且最多 4000 字；该属性不适用于其他字段类型。澄清需求和方案选择优先启用自填，没有合理候选时使用 text；必须对应真实候选 ID 时仍可使用封闭选项。模型按场景选控件：选项少、适合直接比较时优先 radio；选项多、文字长或需要节省空间时选择 select，用户明确指定时遵循用户要求。

标题最长 120 字；最多 16 个字段；字段 ID 非空、唯一且最长 64 字；标签最长 200 字；选择字段须有 1–20 个不重复且非空的选项，每项最长 200 字。围栏内容最多 32 KiB。`required` 缺省为 false；日期未预填时默认本地今天，以 `yyyy-MM-dd` 提交；`time` 为具体时刻，`duration` 为时长，两者复用创建日程的组件选择器。`components` 为 `["hour","minute","second"]` 的非空有序子集，可只显示需要的单位，禁止重复或逆序。time 缺省为时分，未预填时初值为当前本地时间；duration 缺省为分秒，未预填时初值为零。内部值按所选单位顺序以冒号分隔，每段两位；time 小时 00–23、分秒 00–59，duration 首段 00–99、后续段 00–59。默认时分回复仍为 `HH:mm`，完整时分秒为 `HH:mm:ss`；时长及省略单位的组合在用户回复中带明确单位，避免把分秒当作钟点。时间段仍可使用 `select`；文本答案最多 4000 字。未知类型、重复 ID 或不合规结构回退为普通代码。普通 Markdown 代码围栏内的示例不转换为表单。

正文与表单在本轮结束后一起呈现在 Agent 气泡中，完整表单出现后允许填写。停止或断开不展示未完成表单。提交会重新验证存储的表单和选项，再走普通用户消息提交路径，保留输入框草稿与待发送附件。操作仍经 ToolService 按现有授权、确认与执行规则处理。

原始回复及提交后的可读文字保存在既有会话记录中。未提交表单不因后续用户/助理消息或重开历史失效，直到所属历史被删除。提交时，在同一数据库事务中追加用户回复并将字段值写入原始表单消息的展示元数据；非空或空字典都表示已经提交。表单保留原答案、全部字段只读且提交按钮禁用；重开原始分段、模型请求失败或删除后续回复都不会解锁。保存失败则不消费表单，可再次提交。尚未提交的编辑仅驻留当前会话，切换/重开后恢复原始预填；分页裁剪与新会话清理字段状态。提交按钮本身不直接执行系统操作，也不增加单独的模型请求来生成组件。实际首个字段延迟取决于模型首响应、输出顺序和传输速度；本地模拟流验证不等同于真实提供商速度验收。


## 持续对话

产品呈现单一时间线，内部每轮使用新的 sessionID 存储快照。最近正文和相关历史作为有界资料加入请求，不直接拼接历史快照；应用注册仅供内部 Agent 的 history_search 与 history_read，经 ToolService 执行且独立于长期记忆开关。界面及工具保留来源分段标识，工具写入依据本轮意图；本轮明确继续或补充同一未完成任务时可沿用未撤回的授权，不重放已完成或待核实操作。跨轮暂不额外持久化模型生成的摘要或任务数据库，续接依据保留的正文和按需历史读取。

## 主动协助与表单预填

产品提示词先要求利用对话、授权记忆和工具补全信息，合理默认低风险细节，只在关键歧义或必要授权缺失时提问；回复自然、体贴，避免重复确认。`userRequested` 可延续同一未撤回的明确任务授权，额外推断的操作和预填建议不属于授权。权限与操作确认仍由 ToolService 决定。

语气随对话变化，以熟悉用户的视角直接与「你」平等交流，用干净、平实、自然的现代中文打字聊天，信息不全或看不清时坦白说不确定；可以表达关心、欣赏、轻松幽默与有依据的判断，以不加粗的短自然段为主。解释与分析问题时先给出核心判断，再按主次轻重合并展开、用完整句子直接开头，既避免过分比喻/类比/拟人、辩论式反问、评价或判卷式开场、乙方归类称呼、“不是……而是……”对立金句、频繁破折号、强行找补或标签式转折、拔高收尾、每轮硬抛反问、闲聊末尾硬转顾问推下一步，以及整句或段首加粗小标题、“短语+冒号”提纲句、“一是……二是……三是……”和等长平铺清单，也避免为了显得接地气而硬加儿化音、俗词或生硬缩写。用户倾诉时不急着给方案，不机械套用共情开场。准确性落实在核实与行动中，不例行罗列能力限制或未做事项；影响判断或操作的真实问题仍需就近说明，错误直接承认并纠正。

`asky-form` 字段可提供可选 `defaultValue`：文本、单选、日期、时刻、时长使用字符串，多选使用字符串数组。单选必须来自 `options`，仅 `allowCustom:true` 可预填自定义文本；多选不能重复或使用候选之外的值。日期为 `yyyy-MM-dd`，时刻/时长按 `components` 顺序以冒号分隔两位数字。默认值沿用答案的长度、日期、范围校验；类型或值无效时忽略默认值，保留可用字段。

完整且未提交的表单仅为缺少答案的字段提供默认值，显式空字符串或空数组保留为空。提交以存储的表单为准合并默认值并再次校验，保存实际提交快照；预填不会自动提交或批准系统操作。未提交的本地编辑重开后恢复原始默认值；已提交快照原样恢复，不补填遗漏字段。旧表单没有 `defaultValue` 时行为不变。

## DeepSeek 输入缓存

系统提示词保留固定的日期解释规则与配图能力说明，工具目录在同轮续轮期间保持冻结（冷却或配图收尾由运行时拦截和末尾提示约束）。持续对话历史采用锚点追加窗口（上限 40,000 字节 / 80 条对话消息，超限时一次性前推至约 20,000 字节 / 40 条），避免每轮从头部滑出旧消息；本轮相关检索片段（`relevant-history`）、选中引用（`selected-quotes`）、附件文字和本轮时间（`turn-clock`）依次排在固定历史之后、当前问题之前。同轮网页工具结果按顺序分配剩余摘录预算，不回改旧结果。请求以固定的 JSON 键顺序编码。当工具目录、插件说明、记忆或历史锚点批量滚动时，可复用的前缀长度才会重新建立。

DeepSeek 官方端点通过流式响应返回输入 token 的命中数和未命中数。Asky 将两项计数和请求阶段写入 macOS 统一日志的 `ModelCache` 类别。`initial` 表示本轮首次回答请求，`continuation` 表示工具或纠错续轮，`compaction` 表示上下文摘要。命中率按命中数除以两项之和计算。[DeepSeek 缓存规则](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)

在仓库根目录运行以下可选在线测试。`ASKY_CACHE_TEST_CONFIG` 指向已配置的 DeepSeek `ModelConfiguration` JSON，密钥由 Keychain 提供。测试用临时快照、合成历史和只读样品查询完成四轮提问，输出每次请求的服务端计数，消耗所配置账户的 API 额度。

```sh
ASKY_CACHE_TEST_CONFIG=/path/to/model-config.json \
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --package-path Packages/KulaCore --filter CacheLiveTests
```

## 主动配图的真实模型回归

`NativeImageLiveTests` 默认不联网。显式设置 `ASKY_LIVE_IMAGE_MODEL_CONFIG` 为仅包含 `ModelConfiguration` 的 JSON 文件路径后，测试使用其中的服务地址、模型名与 Keychain 引用，经原生 AgentHost/ToolService 运行；密钥只在内存中读取，不写入报告。测试使用临时会话目录和内存数据库，不导入用户历史，固定加入一段“不能贴图”的旧回复来复现能力误判。

```sh
cd Packages/KulaCore
ASKY_LIVE_IMAGE_MODEL_CONFIG=/path/to/model-config.json \
ASKY_LIVE_IMAGE_REPORT=/tmp/asky-image-live.json \
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --filter NativeImageLiveTests
```

默认问题为“钟丽缇是什么明星啊”，检查真实图片读取调用、最终 Markdown 图片及每张图片下载解码。可用 `ASKY_LIVE_IMAGE_QUESTION` 改问题；纯文字负例同时设置 `ASKY_LIVE_IMAGE_EXPECT_TEXT_ONLY=1`。报告包含问题、回答、工具名、图片数量、错误、整轮/首次文字事件耗时、工具耗时与来源尝试、模型轮数及投影大小，不含密钥。首次文字事件可能是工具前说明，不等于最终正文首字；运行时配图校验已计入整轮耗时，测试随后逐张回读缩略图缓存。报告另包含真实候选 URL 与逐图解码结果。钥匙串无法非交互读取时测试失败，不自动弹出授权或修改模型配置。此检查需要服务额度与公网可用性，单次通过不代表所有模型或所有问题都能稳定配图。
